# UI scale 1.5 with screenfit-owned HUD layout

Date: 2026-11-15  
Status: approved in chat; awaiting implementation plan

## Goal

Make the FFXI / Windower UI a bit larger by moving menu scale from **1.45** to **1.5**, keep addon/plugin HUD usable, and avoid fighting overwrites when editing files under `C:\Windower4`.

## Context

- Windower loads from **`C:\Windower4`**. `ffxi-cheeseplate/windower/` is the git mirror.
- Live `settings.xml` currently has `<uiscale>1.45</uiscale>` (1440p preset). Repo mirror may still say `1`.
- Menu scale is read at PlayOnline / Windower launch. Changing it requires a restart to take effect.
- Higher scale shrinks Windower’s UI resolution (`ui_x_res` / `ui_y_res`). Absolute-pixel overlays get a tighter canvas and can overlap chat, party, menus, or each other.
- `screenfit` already reflows a fixed set of overlays when UI size changes (`fit apply` / commit on load and resize).

## Decision: screenfit owns managed layout

**Approach A.** `screenfit` remains the single layout owner for the overlays it already manages. Manual position edits in those plugins’ settings are not the workflow; they can be overwritten on the next apply/resize/startup.

### Screenfit-owned (do not hand-edit for layout)

- Timers (`plugins/settings/Timers.xml` Recast/Buffs/Custom positions + trust filter restore)
- enemybar2 bar positions
- equipviewer position
- FFXIDB map position
- Debuffed, targetinfo, SpeedChecker, findAll tracker blocks that `screenfit` rewrites

Layout changes for these go through `screenfit.lua` constants / `BLOCKS`, then apply.

### Free to edit normally

Any other addon/plugin under `C:\Windower4` that `screenfit` does not rewrite (e.g. GearSwap, InfoBar, scoreboard, keylabels, BattleMod).

## Pass 1 scope (this work)

1. Set live `<uiscale>1.5</uiscale>` in `C:\Windower4\settings.xml`.
2. Update `screenfit.lua` so large / 1440 paths persist **1.5** instead of **1.45**:
   - `scale_for`
   - `PRESETS['1440']`
   - any `//fit scale` paths that hard-code or imply 1.45 as the 1440 default
3. Mirror the same `settings.xml` and `screenfit.lua` changes into `ffxi-cheeseplate/windower/` for git.
4. User restarts PlayOnline / Windower once.
5. Existing `screenfit` load/`fit apply` reflows managed HUD to the new UI size.
6. After login, only fix overlays that still overlap — by changing **screenfit** layout constants, not one-off XML tweaks that the next apply will wipe.

## Out of scope for pass 1

- Full redesign of every overlay position before seeing 1.5 in-game
- Stopping `screenfit` from writing managed settings (rejected; see Decision)
- Window size / borderless vs windowed mode changes
- Changing UI scale for a 1080p preset (stays `1` unless revisited later)

## Success criteria

- After restart, menus render at scale **1.5**.
- `//fit 1440`, `//fit scale 1440`, or `scale_for` on a large window no longer writes **1.45**.
- Managed HUD still loads; obvious collisions after the trial are fixed in `screenfit` only.
- Repo mirror matches live for the files touched.

## Follow-up (pass 2, if needed)

In-game review after 1.5: adjust `TIMERS`, `ENEMYBAR`, `EQUIP`, `MAP`, and/or `BLOCKS` in `screenfit.lua`, then `//fit apply` (or reload) until overlaps are gone.
